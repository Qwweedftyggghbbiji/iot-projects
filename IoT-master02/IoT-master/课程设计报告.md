# 物联网智能网关设计与开发 — 课程设计报告

---

## 一、设计目的

随着我国人口老龄化进程加快，越来越多的老年人在家中独立生活，其居家安全问题日益受到社会关注。传统的家庭安防系统成本高、操作复杂，不适合老年人使用。本课程设计旨在利用 **ESP32-S3 微控制器**，结合 **FreeRTOS 实时操作系统** 和 **物联网通信技术**，设计一款面向银发群体的**智慧居家物联网网关**，实现对居家环境的多维度智能监测与远程告警。

具体设计目标如下：

1. **环境参数实时采集**：通过传感器实时采集温度、湿度、光照强度、可燃气体浓度等环境数据。
2. **人体存在智能检测**：利用 24GHz 毫米波雷达感知家中是否有人，实现人灯联动。
3. **智能照明控制**：根据光照强度和人体存在自动开关白光 LED，节约能源。
4. **远程告警推送**：通过 MQTT 协议将异常数据推送至云端，支持 Web 端远程查看与控制。
5. **紧急求助功能**：通过硬件按钮或 Web 端一键触发 SOS 紧急求助，蜂鸣器报警并推送消息。
6. **数据可视化**：内嵌 Web 服务器，提供实时仪表盘和历史曲线，方便用户直观查看环境状态。

## 二、设计内容与要求

### 2.1 基本功能要求

| 序号 | 功能模块 | 具体要求 |
|:---:|----------|----------|
| 1 | 温湿度监测 | 通过 AHT20 传感器采集温湿度，精度 ±0.3℃ / ±2%RH |
| 2 | 光照监测 | 通过光敏传感器 ADC 采集环境光照，区分明亮/正常/较暗三档 |
| 3 | 燃气监测 | 通过 MQ-2 传感器采集可燃气体浓度，分五级预警（正常/轻度/中度/重度/危险） |
| 4 | 人体检测 | 通过 24GHz 毫米波雷达检测人体存在，支持 IO + UART 双通道 |
| 5 | 智能照明 | 根据光照和人体存在自动开关灯，支持手动/自动模式切换 |
| 6 | 网络通信 | WiFi STA 模式连接路由器，通过 WebSocket 推送实时数据 |
| 7 | Web 仪表盘 | 内嵌 HTTP 服务器，提供移动端适配的实时仪表盘 |
| 8 | 远程控制 | 通过 Web 按钮控制灯光开关、模式切换、SOS 求助 |
| 9 | 一键呼救 | 板载 BOOT 键作为 SOS 按钮，长按触发紧急求助 |

### 2.2 进阶功能要求

| 序号 | 功能模块 | 具体要求 |
|:---:|----------|----------|
| 1 | MQTT 云接入 | 连接 EMQX 公共 MQTT 服务器，实现传感器数据上云 |
| 2 | 历史数据缓存 | 在内存中缓存 120 条历史数据（约 10 分钟），支持 Web 端曲线展示 |
| 3 | 手动开灯超时 | 手动开灯后若 5 分钟无人则自动关灯，避免能源浪费 |
| 4 | 环境告警推送 | 温度超过 35℃ 或湿度过低时，通过 MQTT 发布告警消息 |

│   │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐       │  │

### 3.2 系统软件架构

系统基于 **FreeRTOS** 多任务架构，主要划分为以下任务：

| 任务名称 | 优先级 | 周期 | 功能描述 |
|----------|:------:|:----:|----------|
| `sensor_task` | 5 | 200ms | 采集所有传感器数据，控制 LED，广播 WebSocket，推送 MQTT |
| `ws_server_task` | 4 | 阻塞 | WebSocket TCP 服务端，处理客户端连接与握手 |
| `sos_task` | 3 | 50ms | 扫描 BOOT 键状态，300ms 消抖，触发/解除 SOS |
| `mqtt_task` | 4 | 阻塞 | MQTT 客户端，连接 Broker，处理消息收发 |

### 3.3 数据流设计

```
传感器 (AHT20/光敏/MQ-2/雷达)
    │
    ▼
sensor_task 采集原始数据
    │
    ├──→ LED 控制 (RGB LED PWM)
    ├──→ WebSocket 广播 (实时推送至前端)
    ├──→ MQTT 发布 (数据上云)
    ├──→ 历史缓存 (环形缓冲区，120条)
    └──→ 告警检测 (温度/湿度/燃气)
          │
          ├──→ 蜂鸣器报警
          └──→ MQTT 告警推送
```

### 6.2 任务调度设计

系统采用 FreeRTOS 抢占式调度，任务优先级从高到低排列：

| 优先级 | 任务 | 说明 |
|:------:|------|------|
| 5 | `sensor_task` | 最高优先级，确保传感器采集实时性 |
| 4 | `ws_server_task` | WebSocket 客户端连接处理 |
| 4 | `mqtt_task` | MQTT 网络通信 |
| 3 | `sos_task` | SOS 按钮扫描，无需高实时性 |
| 1 | IDLE | 空闲任务 |

### 6.3 传感器数据采集与 LED 控制流程

```
sensor_task 每 200ms 执行一次：

1. 读取 AHT20 → 温度 t、湿度 h
2. 读取光敏 ADC → light_adc
3. 读取 MQ-2 ADC → gas_adc，计算 gas_level
4. 读取毫米波雷达 → radar_combined (IO + UART 融合)
5. LED 控制逻辑：
   ├─ SOS 激活？→ 红灯常亮（最高优先级）
   ├─ 手动模式？→ 跳过自动控制
   ├─ 燃气 ≥ 重度？→ 红灯
   ├─ 燃气 = 中度？→ 黄灯
   ├─ 光照暗 + 有人？→ 白灯（智能照明）
   ├─ 无人且未超时 + 光照暗？→ 保持白灯
   ├─ 燃气轻度 + 无人？→ 绿灯
   └─ 其他情况 → 关灯
6. MQTT 发布传感器数据
7. WebSocket 广播 JSON 数据
8. 每 5 秒保存历史数据、检测环境告警
```

### 6.4 双通道雷达融合策略

毫米波雷达同时提供 IO 引脚输出和 UART 数据帧两种方式检测人体存在：

```
radar_combined = radar_IO  OR  radar_UART

- IO 引脚（GPIO5）：低电平表示有人，高电平表示无人
- UART 数据帧：解析雷达主动上报的状态帧，提取人体存在标志

双通道融合可提高检测可靠性，任一通道检测到有人即判定为有人。
```

### 7.2 核心代码实现

#### 7.2.1 系统初始化 (`app_main`)

系统入口函数完成 NVS 初始化、事件组创建、硬件初始化、WiFi 连接和任务启动：

```c
void app_main(void)
{
    ESP_LOGI(TAG, "========================================");
    ESP_LOGI(TAG, "  IoT Gateway v2.0  学号: 0207");
    ESP_LOGI(TAG, "  ESP32-S3 + WebSocket + STA");
    ESP_LOGI(TAG, "========================================");

    /* 1. NVS 初始化 */
    esp_err_t ret = nvs_flash_init();
    if (ret == ESP_ERR_NVS_NO_FREE_PAGES || ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
        ESP_ERROR_CHECK(nvs_flash_erase());
        ESP_ERROR_CHECK(nvs_flash_init());
    }

    /* 2. 创建同步原语 */
    g_evt_group = xEventGroupCreate();
    g_sensor_mutex = xSemaphoreCreateMutex();
    ws_mutex = xSemaphoreCreateMutex();

    /* 3. 初始化 WebSocket 客户端数组 */
    for (int i = 0; i < WS_MAX_CLIENTS; i++) ws_clients[i] = -1;

    /* 4. 硬件初始化（传感器、LED、蜂鸣器、雷达） */
    hardware_init();

    /* 5. WiFi 连接（15 秒超时） */
    wifi_init_sta();
    xEventGroupWaitBits(g_evt_group, EVT_WIFI_CONNECTED, pdFALSE, pdTRUE, pdMS_TO_TICKS(15000));

    /* 6. 启动服务 */
    start_http_server();                      // HTTP 服务器（端口 80）
    xTaskCreate(ws_server_task, "ws", 8192, NULL, 4, NULL);  // WebSocket（端口 81）
    xTaskCreate(sensor_task, "sensor", 4096, NULL, 5, NULL); // 传感器任务
    xTaskCreate(sos_task, "sos", 2048, NULL, 3, NULL);       // SOS 按钮任务
    xTaskCreate(mqtt_task, "mqtt", 6144, NULL, 4, NULL);     // MQTT 任务
}
```

#### 7.2.2 WebSocket 服务器

实现基于 TCP Socket 的原生 WebSocket 服务端，支持多客户端并发：

```c
static void ws_server_task(void *arg)
{
    int listen_sock = socket(AF_INET, SOCK_STREAM, 0);
    // ... 配置、bind、listen ...

    while (1) {
        int client = accept(listen_sock, ...);
        // 设置接收超时 5 秒
        struct timeval tv = { .tv_sec = 5, .tv_usec = 0 };
        setsockopt(client, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));

        // 读取 HTTP 升级请求，完成 WebSocket 握手
        char buf[1024];
        int n = recv(client, buf, sizeof(buf) - 1, 0);
        if (n <= 0 || ws_handshake(client, buf, n) != 0) {
            close(client);
            continue;
        }
        ws_add_client(client);  // 加入客户端列表
    }
}
```

WebSocket 握手实现了 RFC 6455 标准，使用 mbedtls SHA1 + Base64 计算 Sec-WebSocket-Accept。

#### 7.2.4 SOS 一键求助

支持板载 BOOT 键和 Web 按钮两种触发方式，带 300ms 消抖：

```c
// 硬件按钮（带消抖）
static void sos_task(void *arg)
{
    while (1) {
        int raw = gpio_get_level(SOS_BUTTON_IO);  // 0=按下
        if (raw != last_state) {
            debounce_start = xTaskGetTickCount();
            debouncing = 1;
            last_state = raw;
        }
        if (debouncing && (xTaskGetTickCount() - debounce_start) >= 300ms) {
            debouncing = 0;
            if (stable_state == 0) {  // 按下
                g_sos_active = !g_sos_active;  // 切换 SOS 状态
                if (g_sos_active) {
                    rgb_led_set_color(RGB_COLOR_RED);   // 红灯
                    buzzer_alarm(60000);                // 蜂鸣器 60 秒
                    mqtt_publish_sos(1);                // MQTT 推送
                } else {
                    rgb_led_off();
                    buzzer_alarm(0);                    // 停止蜂鸣
                    mqtt_publish_sos(0);
                }
            }
        }
        vTaskDelay(pdMS_TO_TICKS(50));
    }
}
```

## 九、系统可行性与创新点

### 9.1 技术可行性

- **主控芯片**：ESP32-S3 是乐鑫推出的高性能 WiFi + BLE 双模 SoC，主频最高 240MHz，内置 512KB SRAM，拥有丰富的外设接口（ADC、I2C、SPI、UART、PWM、USB OTG 等），完全能够满足多传感器采集、网络通信和 Web 服务器运行的需求。
- **操作系统**：FreeRTOS 是成熟的开源实时操作系统，提供任务调度、信号量、队列等同步机制，ESP-IDF 对其有完善的支持。
- **通信协议**：HTTP/WebSocket/MQTT 是物联网领域的标准协议，ESP-IDF 提供了完整的网络栈支持，ESP-MQTT 库已封装好 MQTT 客户端功能。

### 9.2 成本估算

| 元器件 | 参考价格（元） |
|--------|:------------:|
| ESP32-S3 开发板 | 35 |
| AHT20 温湿度传感器 | 5 |
| 光敏传感器模块 | 3 |
| MQ-2 气体传感器 | 8 |
| 24GHz 毫米波雷达 | 25 |
| RGB LED 模块 | 4 |
| 有源蜂鸣器 | 2 |
| 杜邦线+面包板+电阻等 | 10 |
| **合计** | **≈ 92** |

> 总体成本不足 100 元，相比商用智慧居家系统（通常数百至数千元），具有极高的成本优势。

### 9.3 实用性分析

1. **面向银发群体**：系统针对老年人居家安全需求设计，操作简单（一键 SOS、自动照明），降低老年人使用智能设备的门槛。
2. **远程监护**：子女可通过 MQTT 云平台远程查看父母家中的环境状态，收到异常告警推送，及时响应。
3. **节能环保**：智能照明根据人体存在和光照强度自动开关，避免长明灯浪费。
4. **多维度预警**：覆盖温度、湿度、燃气、人体存在、紧急求助等多场景，形成完整的安全防护网。

### 9.4 创新点

1. **双通道雷达融合**：同时使用 IO 引脚和 UART 两种方式检测人体存在，提高检测可靠性，避免单一通道的误报和漏报。

2. **嵌入式 Web 仪表盘**：在 ESP32-S3 内部直接运行完整的 Web 服务器和 WebSocket 服务，无需额外服务器或云平台即可实现实时数据可视化和远程控制，降低系统对外部网络的依赖。

3. **手动开灯超时保护**：手动开灯后若 5 分钟内无人则自动切换回自动模式并关灯，兼顾了用户体验和能源效率。

4. **环形历史缓冲区**：在内存中维护 120 条历史数据的环形缓冲区（约 10 分钟），配合 Chart.js 在前端绘制实时曲线，实现了低资源消耗下的数据可视化。

### 9.5 可维护性与升级路径

1. **模块化驱动设计**：每个传感器独立为一个驱动文件，新增传感器只需添加对应的 .c/.h 文件并在 CMakeLists.txt 中注册。
2. **配置集中管理**：所有引脚、阈值、网络参数集中在 `app_config.h` 中，修改配置无需修改业务逻辑代码。
3. **OTA 升级**：ESP32-S3 支持通过 HTTP 或 MQTT 进行固件远程升级（需后续实现）。
4. **云端接入**：当前 MQTT 已连接公共 Broker，后续可扩展接入阿里云 IoT、华为云 IoT 等平台实现数据持久化和分析。

通过本次物联网智能网关课程设计，我深入了解了嵌入式物联网系统的完整开发流程，从需求分析、系统设计、硬件搭建、软件编码到系统调试，经历了一个完整的产品开发周期。以下是我在本课程设计中的几点体会：

**1. 软硬件协同设计的重要性**

在项目初期，我首先需要根据功能需求选择合适的硬件平台和传感器。ESP32-S3 丰富的接口资源为系统设计提供了充足的扩展空间，但也需要仔细规划引脚分配，避免外设冲突。例如，ADC1 通道同时用于光敏传感器和 MQ-2 气体传感器，需要区分不同的通道号。硬件搭建过程中的接线错误排查，让我深刻体会到了耐心和细致的重要性。

**2. 实时操作系统的任务调度思维**

使用 FreeRTOS 进行多任务编程，让我从传统的裸机编程思维转变为任务调度思维。传感器采集、WebSocket 服务、MQTT 通信、SOS 按钮扫描各自独立为任务，通过信号量和事件组进行同步。这种架构使得系统逻辑清晰、扩展性好。

**4. 物联网协议的实践应用**

本设计涉及 HTTP、WebSocket、MQTT 三种物联网常用协议。WebSocket 实现了实时双向通信使仪表盘数据能够毫秒级更新；MQTT 的发布/订阅模式非常适合传感器数据的云平台推送。通过亲手实现这些协议的客户端和服务端，我对物联网通信架构有了更深刻的理解。

**5. 不足与改进方向**

当前系统还有一些可以改进的地方：一是历史数据仅存储在内存中，掉电后会丢失，后续可接入 SD 卡或 Flash 存储；二是 Web 界面功能仍需完善，如添加用户登录验证、历史数据导出等功能；三是可考虑接入语音播报模块，为老年人提供语音提醒功能。
